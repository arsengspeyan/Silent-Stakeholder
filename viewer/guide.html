How to understand this project

Read this page first. Then open Results. You don't need to read all the code.

Start here — what to open

  • Web This page — understand the pipeline
  • Web Results page — see the top 5 gaps (what judges see)
  • Data gaps.json — raw output with all IDs and scores
  • Code Only if curious: src/score.py (formula) and DEFENSE.md (judge answers)

What happens when you run make viewer

make viewer
# Step 1: copies gaps.json → viewer/gaps.json
# Step 2: starts web server from project folder
# Step 3: open http://localhost:8000/viewer/

That's it. No AI runs. No pipeline runs. It just shows the results file in a nice page.

  • The server runs on your computer only (localhost)
  • The Results page reads gaps.json and draws the cards
  • Click "show evidence" to see sample reviews and GitHub issue links
  • Press Ctrl+C in the terminal to stop the server

What happens when you run make run

This runs the full pipeline — all 5 stages. Takes a few minutes first time, faster after (cached).

make run
# ingest → cluster → label → match → score → gaps.json

After it finishes, run make viewer to see the new results.

The big picture

Two data sources go in. One ranked list comes out.

User reviews (HuggingFace) ──┐
├──► 5 stages ──► gaps.json ──► Results page
GitHub issues (roadmap) ──┘

The 5 parts — one at a time

1
Ingest — get the data
Download PPSSPP reviews + GitHub issues. Give every item an ID like rev_0001 or issue #1823.
Code: src/ingest.py
→ data/reviews.json, data/issues.json
2
Cluster — group similar reviews
Turn each review into numbers (embeddings). Group reviews that mean similar things. No AI here — pure math.
Code: src/cluster.py
→ data/clusters.json (23 groups)
3
Label — name each group
Claude reads sample reviews from each cluster and writes one sentence: "what do these users actually need?"
Code: src/label.py
→ data/labeled_clusters.json
4
Match — compare to GitHub roadmap
For each need, find similar GitHub issues. Decide: IGNORED, UNDER-PRIORITIZED, or MISUNDERSTOOD.
Code: src/match.py
→ data/matched_needs.json
5
Score — calculate confidence & rank
Run the formula. Pick top 5. Write gaps.json.
Code: src/score.py
→ gaps.json (final output)

The confidence formula (memorize this)

confidence = (0.35 × volume) + (0.20 × tightness) + (0.45 × gap_clarity)
  • Volume — how many reviews? (513 reviews = max score for gap #1)
  • Tightness — do reviews say the same thing? (0.52 = somewhat varied wording)
  • Gap clarity — how much does roadmap miss this? IGNORED=1.0, UNDER-PRIORITIZED=0.8, MISUNDERSTOOD=0.6

Gap #1 example:

(0.35 × 0.9991) + (0.20 × 0.5189) + (0.45 × 0.80) = 81.3%

The AI never picks this number. Code in score.py calculates it.

Three verdicts — simple meanings

  • IGNORED — GitHub has nothing about this need
  • UNDER-PRIORITIZED — issues exist but team isn't actively working on it
  • MISUNDERSTOOD — team is working on it, but fixing the wrong thing

Who decides what?

  • Algorithm — which reviews group together, confidence score, ranking
  • AI (Claude) — only names clusters and helps with tricky verdicts
  • You (for defense) — explain why the numbers make sense
