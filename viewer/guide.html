Silent Stakeholder

Find unmet user needs the roadmap is missing — by reconciling app reviews against GitHub issues.

Slide 2 — Problem

Users and teams never sync

Developers plan in GitHub. Users speak in app store reviews. Thousands of reviews pile up while milestones track a different conversation.

Users (silent stakeholders)

  • 9,771 PPSSPP reviews
  • Honest, messy, unfiltered
  • No seat in sprint planning

Team (roadmap)

  • 4,004 GitHub issues
  • 70 milestones
  • Planned work — may miss real user needs
The gap between what users need and what the team builds is invisible without a system to connect both sides.
Slide 3 — What we build

Every gap has four things

Not “513 users said lag.” Each ranked gap is a structured record judges can audit.

1 · The need

Latent user need in plain language — inferred from patterns, not keyword counts.

2 · Confidence

Calibrated score from a fixed formula — 81.3% and 57.3% mean different things.

3 · Evidence

Specific rev_XXXX review IDs + GitHub #NNNN issue numbers.

4 · Verdict

IGNORED · UNDER-PRIORITIZED · MISUNDERSTOOD — vs the roadmap.

Ranked by evidence strength. Strongest gap first. No evidence → no gap.
Slide 4 — How to start

Run the app in four commands

Batch pipeline → artifact → optional QA → read-only viewer.

  1. Setup (once) Copy .env.example → .env, add ANTHROPIC_API_KEY + GITHUB_TOKEN, then pip install -r requirements.txt
  2. Build the report make run — runs 5 pipeline stages → writes gaps.json
  3. QA check (optional) make qa — QA critic grades gaps pass/warn/fail. Does not change scores.
  4. Open the UI make viewer → http://localhost:8000/viewer/
make run
make qa
make viewer
# Viewer only reads JSON — no AI runs at demo time
Re-run is fast: each stage caches to data/. Use make refresh to rebuild everything.

Slide 7 — Clustering

Finding patterns — not summarizing

Different surface complaints → same cluster → same latent need.

  • Embed — sentence-transformers locally (384-dim vectors)
  • Filter — drop reviews < 50 chars ("Good", "Nice")
  • UMAP — 384 → 10 dimensions
  • HDBSCAN — auto cluster count, noise = excluded
  • Result — 23 clusters, each with review_ids + tightness

Example: "GTA lags" · "God of War crashes" · "too slow after update" → cluster c_09 (232 reviews) → merged into gap #1

Cluster membership is ground truth. The LLM never moves reviews between groups.
Slide 8 — Three Claude agents

Same API key · three contracts

All use Anthropic claude-sonnet-4-6. All cached to disk.

Label agent · label.py

Reads ~20 sample reviews from a fixed cluster → writes need + theme. Does not change grouping or scores.

Match agent · match.py

Only when an active open issue matches with high similarity → MISUNDERSTOOD vs addressed. Rules handle the rest.

QA critic · qa_gaps.py

After pipeline: latent need or complaint summary? pass / warn / fail + pitch tips. Read-only — never mutates gaps.json.

Math finds patterns. Claude names and validates. Code scores and ranks.
Slide 9 — Confidence formula

Every % comes from code

confidence = (0.35 × volume) + (0.20 × tightness) + (0.45 × gap_clarity)
  • Volume (35%) — log-scaled review count
  • Tightness (20%) — how similar reviews in the cluster are
  • Gap clarity (45%) — IGNORED=1.0 · UNDER-PRIORITIZED=0.8 · MISUNDERSTOOD=0.6

Gap #1 example → 81.3%

(0.35 × 0.9991) + (0.20 × 0.5189) + (0.45 × 0.80) = 0.8135

513 reviews · UNDER-PRIORITIZED · recalculable from gaps.json

Slide 10 — Verdicts

Roadmap alignment

Ignored

No similar issue (similarity < 0.35). Team may not know this need exists.

Under-prioritized

Issues exist but closed, stale, or not on open milestones.

Misunderstood

Team works on related problem — wrong angle. Or shipped fix, users still complain.

Example · Black screen (#10, 63.9%)

Issue #15469 shipped in v1.14.0 for Raspberry Pi. Android users still report black screens. MISUNDERSTOOD — fixed narrow case, not general failure.

Slide 12 — Latent need example

Not a complaint summary

Summarizer (bad)

"513 users complained about slow games."

Silent Stakeholder (good)

"Users need consistent performance across all PSP titles regardless of game size, graphics type, or device specs."

Surface complaints (what users literally said)

  • GTA lags on certain titles
  • 2D games lag while 3D titles run fine
  • Specific games crash mid-mission
  • Android slower than PC/Linux

Hidden need: Predictable playability per game×device — users never wrote that sentence.

Proof: 513 review IDs in gaps.json + merge_reason in score.py + GitHub issues #15281, #14074.
